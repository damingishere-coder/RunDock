# Alter 项目行紧凑改版与网页入口恢复任务

## 背景

新的项目页把项目名和备注都做成整列宽度的编辑按钮，容易在空白区域误触；项目名、状态、资源和操作又被四个固定列拉开。旧进程页已有网页端口按钮，但 `/processes` 切换到项目页后没有接回该能力。

## 目标

- 保持现有项目名不变且不可在项目页编辑，只允许编辑备注。
- 名称与备注并排，压缩状态、资源和操作区域，消除无意义空白。
- 在项目行恢复单端口直开、多端口选择的网页入口。
- 保持项目分组、启停、技术组件展开和日志入口不变。

## 允许修改范围

- `web-ui/src/pages/ProjectsPage.tsx`、`web-ui/src/pages/ProcessesPage.tsx`。
- `web-ui/src/components` 中与网页按钮直接相关的共享组件。
- `web-ui/src/lib/processWeb.ts` 及对应前端测试。
- 本任务文件、构建产物和本机可恢复安装备份。

## 禁止修改范围

- 不修改 Rust 项目 API、项目持久化结构和 `%APPDATA%/alter-pm2/projects.json`。
- 不修改或重命名底层进程，不 reset、stash、覆盖已有工作区改动。
- 不提交、推送、发布或部署到远程环境，不读取或输出 secrets。

## 已确定实现要求

- 项目名为普通文本；备注为内容宽度的紧凑编辑控件，空备注显示“添加备注”。
- 编辑备注只提交 `{ note }`；Enter/保存提交，Escape/取消放弃，不在失焦时自动保存。
- 项目行按“标识、状态资源、分类与操作”紧凑排列，窄宽度允许状态信息换行但不得横向溢出。
- 端口只接受监听中的 TCP；使用端口 PID 和 `ancestor_pids` 归属到项目成员 PID，并去重排序。
- 单端口直接打开，多端口弹出选择菜单，无端口不显示，SSH 连接显示禁用提示。
- `display_name` 字段和后端兼容能力继续保留，但项目页不得提交该字段。

## 验收标准

- `AI JobPilot` 与备注同行，名称不可编辑，空白区域不会触发编辑。
- 备注保存请求不包含 `display_name`，取消编辑不发请求。
- 状态、组件数、CPU、内存集中显示，当前和较窄桌面视口均无横向溢出。
- 有端口项目显示网页入口；分类、启停、展开和日志入口保持正常。
- 八个项目及现有名称、备注、分类和状态数据不变。

## 测试命令

- `npm test -- --run`（`web-ui`）
- `npm run build`（`web-ui`）
- `npm run lint`（`web-ui`，既有失败单独报告）
- `cargo build --release --target x86_64-pc-windows-gnu`
- 当前本机 `/processes` 页面浏览器烟雾与布局验收。
